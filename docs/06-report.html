06 / REPORT

Build a report a reader can follow.

Put the question, dates, numbers, charts and limits in an order that makes sense to someone who did not build the report.

REPORT VIEW BUILD THE PAGE CHECK THE STORY

The LMS asks for summary cards, store-department detail, a tooltip, slicers, interactions and a forecast. Put them in an order that takes the reader from the main numbers to the evidence behind them.

Put the page in a sensible order

1

Title and purpose

What is this page about, for whom and for which dates?

2

Key numbers

Show the important numbers with units and dates.

3

Charts and detail

Show comparisons and trends that explain the numbers.

4

Limits

Say what the data does not prove and what to check next.

Define every number on a card

Report element What it means Check
Total sales Sum of Weekly_Sales for the selected dates and filters. Could joining tables have counted the same sale twice?
Peak value The largest value at a named level: store, department, date or store-date. Would a different grouping give a different peak?
Median temperature The middle Temperature value for the selected rows. Are the dates and rows included clear?
Forecast A future estimate made by Power BI. Is it labelled as an estimate, not a past result?

Build the report page

1

Set the title and dates

Write the page title, audience, dates and reading order before arranging charts.

You should see: a page with one clear job, not a gallery of spare charts.
Why: a reader needs to know what the page is for before reading the charts.
2

Add summary cards

Add cards for total sales, markdowns or other agreed numbers. Label the units and dates.

You should see: cards whose values change as expected when you use the filters.
Why: a number without a name, unit or date is easy to misread.
3

Add store and department detail

Add a comparison chart so the reader can move from the overview to a store or department.

You should see: a visual that supports the detail question rather than repeating a summary card.
Why: detail should explain a difference, not just fill the page.
4

Add useful tooltip detail

Create a tooltip page when extra detail helps explain a mark. Give it a clear title.

You should see: extra detail that answers a follow-up question without hiding the main chart.
Why: a tooltip is extra help, not a place to hide an important number.
5

Add slicers and interactions

Use a slicer for the choice the reader is allowed to change. Set filter, highlight or none deliberately.

You should see: the charts you chose respond, while unrelated charts still make sense.
Why: clicking is part of how the report works.
6

Change the date filter

Change the dates and recheck totals, peaks, notes, forecasts and written conclusions.

You should see: the story remains honest under a new selection.
Why: a note that was true for one date range may be wrong for another.

Say what the chart shows and what it cannot prove

O

What it shows

The values and pattern you can see.

I

What it might mean

A possible reason for the pattern.

C

What it cannot prove

The limit of the data or chart.

Q

What to check next

The next piece of evidence you need.

Check the report before sharing it
  1. Can a reader name the question, period and measure?
  2. Does every summary card have a definition and unit?
  3. Does the forecast carry a clear caveat?
  4. Does the report distinguish observation from interpretation?

Check: ask someone else to explain the page without you translating it.

Code Institute LMS exercise: assemble the Retail report

This is the report-page example built from the Retail tables. Start with the cleaned and linked tables; do not build a page from fields you have not checked.

Required report components

  1. Add summary cards for agreed sales/markdown measures and label their period and units.
  2. Add store–department detail so the reader can move from the overview to a specific comparison.
  3. Create a dynamic tooltip page, a slicer and clear click behaviour.
  4. Review the sales trend and forecast as an estimate, then add bookmarks and notes that still match the selected dates.
Primary source: sales data-set.csv.

Use the other tables to explain the sales

Use Features data set fields such as Markdown1, Temperature and Date to explain a sales pattern, while stores data-set supplies store details. Say which table and row meaning each number uses.

Final report check: change the date or Store selection and re-read every card, note and forecast statement.
Supporting sources: Features data set.csv · stores data-set.csv.
