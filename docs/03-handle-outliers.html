03 / HANDLE OUTLIERS

A strange value needs checking before you change it.

A very high or low value may be a mistake, a real event or a unit problem. Look at the rows first. Then decide whether a rule is needed.

POWER QUERYCHECK THE VALUESWRITE THE RULE

The Retail files contain negative Markdown values and negative Weekly Sales values that the exercise asks us to handle. A negative Temperature is different: cold weather can be below zero. The correct action depends on what the column measures.

How to investigate a strange value

1

Ask what the column measures

A minimum that is impossible for sales may be perfectly normal for temperature.

2

Find the unusual values

Use the minimum, maximum and profile to find rows worth inspecting.

3

Look at the rows

Filter the table temporarily, inspect the rows, then remove the filter before writing a correction.

Looking at a value is not the same as changing it

A conditional column remembers the rule for the next refresh.

Do this in Power Query

1

Profile the candidate field

Inspect Markdown2 and note the minimum shown by the profile.

You should see: the lesson identifies a negative minimum, including -35.74 in its example.
Why: a negative Markdown amount is suspicious for this field, but the profile alone does not explain why it occurred.
2

Filter to investigate

Open the Markdown2 menu → Number Filters → Less than → enter 0.

You should see: only rows containing negative Markdown2 values.
Why: inspect the exact affected records before choosing a correction.
3

Remove the temporary filter

Delete the investigation filter from Applied Steps before returning to the full table.

You should see: all rows again and the original profile scope restored.
Why: an investigation view must not silently become a row-removal rule.
4

Write the rule

Choose Add Column → Conditional Column. If Markdown5 is less than 0, return 0; otherwise return the original value. Name it Handled Markdown5.

You should see: a new column with zero for negatives and the original value for positives.
Why: the rule is visible, repeatable and testable.
5

Replace the field carefully

Remove the original column, rename the handled column to Markdown5, set its type to Decimal Number, and choose Home → Close & Apply.

You should see: one consistently named corrected field in the model.
Why: the report uses a stable field name while the query retains the transformation history.
6

Transfer the pattern

For sales data-set, create Weekly_Sales_Adjusted with the same conditional logic, then replace and rename only after validation.

You should see: negative weekly sales handled without deleting their rows.
Why: transfer tests whether you understand the decision pattern rather than memorising one column name.

Use the meaning of the column

FieldWhat looks unusualWhat it may meanWhat to do
Markdown2Negative minimumNot allowed by the exercise rule, or a source problem.Inspect the rows, then apply the conditional correction.
Weekly_SalesNegative valueHandled as an invalid sales amount for this exercise.Use the same conditional idea and check the result.
TemperatureNegative valueCold weather can be below zero.Do not change it just because it is negative.
Remember: a minus sign tells you the number is below zero. It does not tell you whether the value is wrong.
Check your understanding before building visuals
  1. Why is the minimum only a starting point?
  2. What happens if you leave the inspection filter in Applied Steps?
  3. What would justify changing a negative value to zero?

Answer: explain what the column measures, separate a temporary filter from a permanent change, and name the evidence that supports the correction.
