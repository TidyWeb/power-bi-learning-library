01 / IMPORT AND PROFILE

Before we clean anything, we need to know what arrived.

Power Query can remember the steps you take, but it cannot tell you whether the files answer the client’s question. Import is your first look at what arrived.

POWER QUERYTABLE VIEWPROFILE GATE

Suppose the client says, “Give us a reliable picture of retail performance.” Before choosing a chart, list the files, check whether the columns and dates make sense, and use the row-meaning question from Start Here: what is this row about?

What arrived?

Reminder from Start Here: “What one row is about” is not a list of every column. It names the record. The other columns give details about that record. In Sales, for example, the row is about one department in one store for one week; Weekly_Sales tells us how much was sold.

From file to Power BI table

Do this in Power BI Desktop

1

Connect to the file

Choose Get data and select the supplied file. Read the columns instead of guessing what the filename means.

You should see: the connector or preview with the available table or sheet.
Why: the file name does not tell you what each row or column means.
2

Choose Transform Data

Open Power Query before loading the file so you can inspect and clean it.

You should see: Power Query Editor with the query and a preview of the rows.
Why: a preview helps you inspect the file before it becomes part of the report.
3

Write down what one row describes

For each table, complete the sentence “one row describes …”. Then note which columns together identify that row.

You should see: a short list saying what each table is about and which columns may link it to another table.
Why: if you do not know what a row means, you cannot know what a total means.
4

Check the whole file

Use Column quality, Column distribution and Column profile. Check whether Power BI is showing the first 1,000 rows or the whole table.

You should see: counts of valid, empty, error, distinct and repeated values.
Why: the first rows can look fine while a later row contains a problem.

What to look for in the preview

Look at the values before changing anything

Check what values occur, how often they occur, and whether their type matches what the column is supposed to hold. The profile helps you decide what to do; it does not decide for you.

Questions to answer

  • What type of value is in each important column?
  • Which values are empty, written as words such as NA, or errors?
  • Which columns are unique, and which repeat?
  • Does the preview cover the whole table?
  • Are the dates and stores the ones the client needs?
Stop here if you cannot explain: what one row describes, which columns identify it, and what the unusual values mean.
Before you start cleaning

Question: Why is “the first 1,000 rows look fine” not enough?

Answer: a later row may contain an error, missing value or unexpected category. Check the whole table before you decide on a cleaning rule.
